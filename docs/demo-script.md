# 本機作品展示（約五分鐘）

開啟 [本機介面](http://127.0.0.1:3000)。目前資料：工務局 1,043 筆決標紀錄、捷運公司 52 筆預算案件、工程會兩份程序文件共 22 個段落。啟動方式見 [local-demo.md](local-demo.md)。

1. **資料來源（30 秒）**：點「資料來源」，展示實際筆數、期別及最近同步。說明來源期別不是決標日期。
2. **條件查詢（60 秒）**：點首頁範例「找捷運公司預算300萬到1000萬元的案件」，再送出。此快照有 7 筆，預算與決標分欄；缺少決標值時顯示「未提供」。說明中文條件轉換為參數化 SQL。
3. **相似案件（60 秒）**：點首頁北安抽水站相似案件範例並送出，查看相似案件與來源。說明案件與文件向量分開保存；先取向量候選，再套 SQL 條件。
4. **文件引用（60 秒）**：點「依開標作業程序，開標前應通知哪些人員？」並送出。展示回答及第 1、2 頁來源連結；連結附帶 `#page=`，是否跳頁取決於 PDF 閱讀器。說明文件僅有 JP01／JP03 指定版本。
5. **資料不足（30 秒）**：輸入「資訊服務案件的歷史決標金額區間？」。現有資料缺少決標日期，有效比較樣本為 0，應明確說明樣本不足，不產生區間。
6. **評測與限制（60 秒）**：展示 [十題原始實測](../backend/evals/local-demo-raw.json)與[作者／代理檢查](../backend/evals/local-demo-review.json)。十題皆執行，但兩題廣泛文件問題未通過語意檢查；Recall@5 尚無完整相關標註，維持 null。引用 ID 有效不代表答案語意正確。

每次生成的文字可能不同，展示時以案件表、價格樣本狀態與原始頁碼核對結果。模型逾時或驗證未通過時會保留案件並顯示限制，不保證每次都有完整摘要。

履歷摘要：建立以 FastAPI、Next.js、PostgreSQL、Qdrant 與模型 API 組成的採購 RAG 助理；實作官方 API 匯入、向量檢索、增量文件同步、確定性價格樣本篩選、引用驗證與可追溯實測紀錄。
