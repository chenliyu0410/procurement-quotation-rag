# 面試展示流程

展示前先完成實際 CSV 同步、`sync-case-vectors`、文件同步與模型設定，確認 `/api/query` 非 `configuration_required`。本地測試通過不代表已通過公開資料評測，請勿引用原先預填的 100% 或 P95 數字。

1. 說明問題：公開採購資料分散，歷史價格與規範難以一起查詢。
2. 查詢「找出預算 300 萬到 500 萬元的資訊設備案件」，展示中文條件解析與參數化 SQL。
3. 查詢相似案件，展示獨立案件向量 collection 與固定 point ID。
4. 展開歷史決標金額參考，說明同分類、近五年、Top-10、至少五筆與 IQR 規則。
5. 詢問採購程序，點開文件頁碼引用，說明相鄰 chunk 與七段 context 上限。
6. 問一個資料外問題，展示拒答與限制。
7. 開啟資料來源頁與評測結果，說明可重跑同步及 embedding 版本隔離；未標註指標呈現 `null`，只報告有原始查詢紀錄支持的數字。

履歷摘要：建立以 FastAPI、Next.js、PostgreSQL、Qdrant 與付費模型 API 組成的採購 RAG 助理；實作公開資料 ETL、混合檢索、可重入向量索引、確定性價格統計、引用驗證與固定評測集。
