# 採購與報價知識助理：第一版設計

## 1. 專案意圖

本專案是一個可公開展示的採購與報價知識助理，用於求職作品集。它模擬企業業務、採購或專案人員整理採購案件、歷史報價與採購規範的工作，讓使用者以自然語言查詢案件、比較價格、尋找相似案例，並取得有來源依據的報價參考資訊。

第一版使用臺北市資料大平臺的公開資料，避免公開展示涉及公司機密。系統架構保留未來匯入公司內部 PDF、CSV、Markdown 與文字檔的能力。

## 2. 目標

- 建立可從公開網址操作的 Web 應用程式。
- 支援自然語言查詢採購案件的金額、分類與日期。
- 結合 SQL 精確查詢與向量語意搜尋。
- 搜尋與需求相似的歷史採購案件。
- 根據公開歷史資料產生可解釋的報價參考區間。
- 回答採購程序問題，並引用文件名稱、頁碼或原始資料連結。
- 資料不足時明確說明限制，不產生虛構案件或數值。
- 提供固定測試集與評測結果，展示系統可靠度。

## 3. 非目標

第一版不包含：

- 自動投標或向外部機關送件。
- 具有法律或商業承諾效力的正式報價。
- 付款、合約簽署或企業簽核流程。
- 多租戶企業權限與長期私人文件保存。
- 自動判定得標機率。
- 只憑語言模型生成未經資料支持的報價數字。

## 4. 使用者與主要情境

主要使用者是希望快速整理公開採購資訊的業務、採購與專案人員，以及檢視作品的面試官。

典型流程：

1. 使用者進入網站，無須登入即可查詢內建公開資料。
2. 使用者輸入需求，例如「找出預算 300 萬至 500 萬元的資訊設備相關案件」。
3. 系統解析金額、日期、機關、分類與文字需求。
4. 系統以 SQL 篩選結構化資料，並以向量搜尋尋找相似標案或規範段落。
5. 系統呈現案件比較、價格統計、參考區間、推算理由與來源。
6. 若證據不足，系統說明缺少哪些資料及無法判斷的部分。

## 5. 第一版資料來源

第一版優先使用：

- 臺北市政府工務局採購案件：歷史標案名稱、分類與總決標金額。Dataset ID：`2be36284-8463-495c-bcff-fc45d403efac`，資料集頁：`https://data.taipei/dataset/detail?id=2be36284-8463-495c-bcff-fc45d403efac`。
- 臺北捷運公司採購案件預定招標時程：採購案名、預算金額、標的與預定月份。Dataset ID：`f4fd7f03-9bf6-41de-a003-02c437596570`，資料集頁：`https://data.taipei/dataset/detail?id=f4fd7f03-9bf6-41de-a003-02c437596570`。
- 臺北市政府採購作業手冊中的「招決標方式評估流程」PDF：採購分類、金額級距、同質／異質判斷與招決標方式。Dataset ID：`a7e84479-2c8c-41db-8572-8b51197910db`，Resource ID：`f06a7bf4-9b60-4e86-95b7-7cd0ea8c0eb4`，下載網址：`https://data.taipei/api/dataset/a7e84479-2c8c-41db-8572-8b51197910db/resource/f06a7bf4-9b60-4e86-95b7-7cd0ea8c0eb4/download`。

來源資料以公開 API 或 CSV 下載；每筆紀錄保存來源資料集、原始連結、資料更新時間與擷取時間。公開展示版只使用可公開散布的資料。

CSV 的實際 resource URL 不寫死在應用邏輯中；資料擷取器先從資料集頁或官方資料集介面解析當期資源，並將使用的 resource ID 記入同步紀錄，以支援按期新增檔案的資料集。

第一版不要求支援所有 data.taipei 資料集。新增資料源時必須先建立欄位映射與資料品質檢查。

## 6. 功能範圍

### 6.1 自然語言案件查詢

支援依機關、案件名稱、分類、日期、預算與決標金額範圍查詢。數值篩選、排序、聚合與日期計算由程式及 SQL 執行。

### 6.2 相似案件搜尋

以案件名稱、標的分類及可取得的文字描述建立搜尋文本，使用向量相似度找出候選案件，再結合金額範圍、資料時間與關鍵詞進行排序。

### 6.3 報價參考分析

輸出內容包括：

- 3 至 5 個相似案件。
- 各案件的預算或決標金額。
- 樣本數、最小值、最大值及中位數。
- 參考價格區間及計算方法。
- 可能影響價格但資料中缺少的條件。
- 資料期間與更新時間。

報價區間由後端的確定性計算產生。語言模型只負責解釋結果，不直接創造數值。第一版不輸出正式報價單檔案。

第一版將此結果命名為「歷史決標金額參考區間」，不宣稱為足以投標的建議價格，計算規則如下：

1. 只有具有效 `award_amount` 的歷史決標案件能進入價格樣本；預算金額與決標金額不得混在同一統計分布中。
2. 先以正規化後的標的分類篩選，再以案件名稱與描述的語意相似度排序；前端列出實際納入的案件。
3. 去除重複案件及金額小於等於零的紀錄。第一版不因金額大小自動刪除離群值，以免在樣本少時隱藏真實案件。
4. 有至少 5 個可比較案件時，主要參考區間採第 25 百分位數至第 75 百分位數（IQR），並一併顯示中位數、最小值、最大值與樣本數。
5. 少於 5 個案件時，不產生參考區間，只列出個別案件與「樣本不足」提示。
6. 未來招標資料中的 `budget_amount` 僅用於需求篩選與預算比較，不用來替代歷史 `award_amount`。
7. 因公開資料缺少數量、規格、工期與風險條件，系統必須在結果中列出這些限制。

### 6.4 採購文件問答

使用向量搜尋擷取相關文件段落，回答時顯示文件名稱、章節、頁碼與來源連結。沒有足夠相關段落時拒絕下結論。

### 6.5 來源與資料狀態

網站提供資料來源頁，顯示資料集名稱、涵蓋期間、最後同步時間、紀錄數量及同步狀態。

### 6.6 展示用文件上傳

第一版可將文件上傳設為延伸功能。若納入，僅支援 PDF、Markdown 與純文字，檔案只保留於當次工作階段並設定大小限制。公開資料的核心展示不依賴上傳功能。

## 7. 系統架構

### 7.1 元件

- **Web 前端：** Next.js，提供聊天輸入、條件篩選、案件比較表、引用與資料來源頁。
- **後端 API：** Python 與 FastAPI，負責查詢路由、資料分析、RAG 編排與回應格式。
- **關聯式資料庫：** PostgreSQL，保存案件欄位、來源與同步紀錄。
- **向量搜尋：** pgvector，保存案件搜尋文本與文件片段向量。
- **模型服務：** 付費語言模型及 embedding API；供應商透過介面封裝，金鑰只存在後端環境變數。
- **資料管線：** 定期下載 API/CSV、正規化欄位、解析 PDF、切分文字、建立向量及記錄錯誤。
- **部署：** 前端、後端與託管 PostgreSQL 可分開部署，整體提供公開 HTTPS 網址。

第一版以管理命令執行全量、可重入的手動同步，部署前及展示資料需要更新時執行；網站顯示最近成功同步時間。自動排程、增量同步、重試告警列為第二版功能，因此第一版不依賴常駐 scheduler。

### 7.2 查詢流程

1. 前端將問題送到後端。
2. 後端解析查詢意圖與結構化條件。
3. 查詢路由決定使用 SQL、向量搜尋或兩者。
4. SQL 回傳精確案件與統計資料。
5. 向量搜尋回傳相似案件或規範片段。
6. 後端對候選證據去重、過濾與排序。
7. 語言模型只能根據提供的證據生成說明。
8. 後端驗證回應引用的案件 ID、金額與來源存在於證據集中。
9. 前端呈現答案、案件卡片、統計與可點擊來源。

### 7.3 資料模型

採購案件至少包含：

```text
agency
case_id
case_name
category
budget_amount
award_amount
announcement_date
expected_tender_date
source_url
source_dataset
source_updated_at
ingested_at
```

文件片段至少包含：

```text
document_id
document_title
section
page_number
chunk_index
chunk_text
source_url
embedding
```

## 8. 介面範圍

第一版包含三個主要介面：

1. **查詢首頁：** 專案說明、範例問題、聊天輸入與常用篩選條件。
2. **回答結果：** 摘要、相似案件比較表、價格統計、限制說明及來源引用。
3. **資料來源頁：** 資料集、涵蓋期間、資料量、更新時間及同步狀態。

介面需適合桌面與手機瀏覽。面試展示以桌面版為主。

## 9. 可靠性與安全限制

- SQL 使用參數化查詢；語言模型不能直接執行任意 SQL。
- 金額統計由後端程式計算，並保留輸入樣本。
- 回答只能引用本次檢索到的證據 ID。
- 引用必須能連回原始資料或顯示文件頁碼。
- 模型 API 金鑰不傳送至瀏覽器或提交至 Git。
- 公開展示加入請求頻率限制、檔案類型與大小限制。
- 網頁抓取僅處理允許使用的公開來源；第一版優先使用官方 API/下載檔案。
- 系統明確標示報價為公開資料推算結果，不能視為正式投標建議。

## 10. 測試與評估

建立至少 10 個固定測試問題，涵蓋：

- 金額範圍查詢。
- 日期與機關篩選。
- 相似案件搜尋。
- 報價統計計算。
- 採購文件問答。
- 查無資料與超出範圍問題。

10 題固定評測集由專案作者根據已鎖定的資料快照人工建立，每題保存問題、預期查詢條件、相關案件或文件片段、允許的答案要點，以及是否預期拒答。資料快照變更時須重新產生或人工複核標註。

驗收指標：

- 金額與日期結果和直接資料庫查詢一致。
- 回答中的案件、金額及來源均能在證據集中找到。
- 文件型回答能顯示文件名稱及頁碼。
- 無證據的測試問題不產生虛構案件。
- 10 個預設問題能在公開網站完成查詢。

第一版量化門檻：

- 結構化金額與日期查詢正確率：100%。
- 引用有效率（引用 ID 可解析且存在於本次證據集）：100%。
- 文件檢索 Recall@5：至少 80%。
- 人工判定的回答證據支持率：至少 90%。
- 預設無答案問題的正確拒答率：100%。
- 公開站台正常狀態下的端到端回應時間以 P95 低於 10 秒為展示目標；外部模型服務延遲不作為 CI 阻擋條件，但須記錄。

另記錄檢索命中率、引用正確率、回答是否有證據支持及回應時間，作為 README 的評測結果。

## 13. 完成定義

當公開網站能以內建公開資料完成預設問題、所有數值與引用可追溯、查無證據時能拒絕推測、評測與文件齊全，即視為第一版完成。
